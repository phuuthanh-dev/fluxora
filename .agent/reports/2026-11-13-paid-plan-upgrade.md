# Full-price paid upgrade — implementation evidence

- Scope: task `.agent/tasks/2026-11-13-paid-plan-upgrade.md`; full-price Starter→Pro resets paid term and live-run quota only after verified payOS settlement. Remaining Starter time is not credited; the next regular quota reset remains UTC month start. Same-plan renewal preserves quota and extends the paid term.
- Safety: a workspace-row lock serializes payment settlement and live-run claims. Upgrade orders record the Starter expiry the owner reviewed; if a different active paid term is present at settlement, the order remains in REVIEW. Existing order verification and duplicate-payment protections remain; usage records are not deleted.
- Database: two additive migrations were applied to a fresh isolated database and the existing local `workflow` database. No production data, actual payOS checkout, or real payment was touched.
- Actual UI review: disposable local account, isolated database and fake payOS configuration; upgrade confirmation inspected desktop light/dark and 390px mobile, pricing and terms viewed directly. Terms-section anchor was adjusted after visual review. These observations do not cover every browser or screen.
- Final local gate: `npm run verify` passed harness, migration validation, 1,239 API tests (one optional skip), 78 web tests, typechecks and builds. Browser suite returned 260/261 because the new paid-return test omitted mocked identity/provider fields. Corrected that fixture and reran `e2e/plan-usage.spec.ts`: 5/5 passed. Full clean CI on the exact PR head is required; do not claim that the local root verify passed.
- Final review added a guard against resuming an old checkout after the paid term changes. The first focused test command ran from the wrong directory and could not load the API decorator configuration; rerunning from `apps/api` passed 9/9 billing tests, including the real isolated-PostgreSQL concurrency test.
- Bounded read-only load: 100 local authenticated plan-usage requests, concurrency 10, 0 failures, median 6ms, p95 30ms. One synthetic account, local machine and isolated database; no conclusion about 100 independent users, VPS limits, provider load, or production throughput.
- n8n Cloud monthly upgrades apply features immediately but use its subscription rules and do not reset the month's executions. Fluxora's prepaid/full-price/allowance-reset policy is owner-selected and deliberately different. Source: https://support.n8n.io/article/changing-your-plan-billing-and-proration and https://support.n8n.io/article/can-i-add-more-executions.
- Existing GSAP target and software WebGL warnings appeared in passing landing tests. No new offsite backup work was undertaken at the owner's request.
