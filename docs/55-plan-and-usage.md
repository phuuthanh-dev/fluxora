# Plan and usage — phase one

> Historical design record. Production status as of 2026-11-13 is summarized in the live qualification note in [payOS checkout](56-payos-checkout.md). Workspace-count proposals below are not offered or enforced.

Owner-approved 2026-11-12: provide an observational Free / Starter / Pro plan experience. Proposed prices are 0 / 99,000 / 199,000 VND per month; proposed monthly live-run allowances are 1,000 / 3,000 / 10,000, active workflows 5 / 15 / 50, workspaces 1 / 2 / 3 and concurrency 1 / 2 / 3. These amounts are not payment offers, performance guarantees or enforced entitlements. Payment, subscriptions, hard quota, automatic downgrade enforcement, trial notifications and the team plan are outside this release. Existing workflows, connections and users continue unchanged.

The plan is scoped to a workspace; a platform admin may explicitly assign a 7, 14 or 30 day Starter or Pro trial, or reset it to Free. Expired trial metadata resolves to Free without a scheduled job. Changes serialize on the workspace and are written with actor and before/after metadata to the existing audit log. Only the separately authenticated platform administrator may manage trials. This assignment does not grant permissions, charge money or restrict workflow behavior.

The workspace owner may inspect a UTC-calendar-month count of retained LIVE executions whose `startedAt` falls in that month, plus its current active workflow count. This includes live manual and node-debug executions and excludes mock runs, queued runs not yet started and continuation/retry phases of the same execution. A manually retried execution is a new record. Existing execution retention can remove records before month end: the displayed count is a **minimum**, not a complete meter. There is no retroactive backfill and this number must not be used for billing or hard quota. Safe complete accounting across deletion, retries, crash recovery and all creation paths is future work.

Follow-up in development: the database records each live execution's first start atomically in `UsageRun`, independently of execution retention, with a unique execution ID and a workspace index. The installation time is recorded in `UsageMeter`; earlier executions are not fabricated or backfilled. The workspace shows this prospective count separately from the retained-history minimum. During the first partial month, the tracked count cannot represent the entire month. No number is used to bill or enforce a limit until deployment, multi-process behavior, retry/continuation and accounting have been independently qualified. A migration must be applied before application code reading these tables; the trigger also covers old workers during the rolling deployment.

Catalog prices and workspace/concurrency numbers are proposals, not enforcement; the proposed workspace count is an owner-level benefit that is not currently modeled or limited. AI uses the user's own provider credentials and third-party charges remain theirs. Retention remains the existing system-wide policy. The UI uses the shared product shell, design tokens and controls; the admin trial action is part of existing Workspaces rather than a separate admin area.

Comparison: [n8n pricing](https://n8n.io/pricing/) describes a workflow execution as one complete workflow run regardless of the number of steps, and distinguishes plan allowances and concurrency. Fluxora's present retained-history count is intentionally not claimed to be equivalent to n8n's billing accounting. No production capacity, trial conversion, paid service or provider qualification is implied by this design.

## Benefits comparison and public pricing

- n8n Cloud publishes execution allowances, concurrency, shared projects, AI assistance, history, administration and different hosting options. It states that plans include all integrations and unlimited workflows; Fluxora's proposed active-workflow limits and current workspace model are not n8n parity. [n8n pricing](https://n8n.io/pricing/)
- Zapier compares tasks, polling intervals, multi-step flows, shared workspaces, admin and support across tiers. Fluxora cannot claim equivalent integration coverage, collaboration or paid-tier features. [Zapier pricing](https://zapier.com/pricing)
- Make charges credits for operations; Fluxora's proposed run-based approach is easier to explain for a multi-step workflow, but the product has not established comparative economics or capacity. [Make pricing](https://www.make.com/en/pricing)
- Fluxora can honestly highlight its visual editor, supported integrations, mock runs, execution details, user-owned AI keys and self-hosting separately from managed cloud plans. Provider availability, feature coverage and third-party charges vary; there is no promise that every integration works for every user.
- `/pricing`, landing navigation/footer and workspace cards use the same provisional catalog. The landing capacity planner remains explicitly illustrative, not a pricing calculator. Trial and proposed concurrency/workflow limits remain unenforced; workspace-count benefits are not offered because paid ownership is workspace-scoped.
- PayOS remains a later checkout milestone: the owner has an account. Its documentation states testing uses real transactions, not a separate sandbox. No live transaction, key, automatic renewal or payment has been implemented in this phase. [payOS test environment](https://payos.vn/docs/moi-truong-test/)
